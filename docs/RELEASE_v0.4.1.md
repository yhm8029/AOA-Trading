# v0.4.1 — 잘린 잔고 시간 형식 수정

## 업데이트
새 ZIP을 새 빈 폴더에 풀고 `start_windows.bat`를 실행합니다. 기존 앱 또는 local-data 폴더를 선택하여 주문·시세·메모 사본을 유지합니다. 자동으로 열린 새 탭의 v0.4.1을 확인하세요. Python 3.10 이상이 필요합니다.

**기존에 선택했던 `aoa-wallet-2018-03-01-2021-12-31.csv`를 잔고 연결에서 한 번 다시 선택하세요.** 파일명 변경·잔고 초기화·시세 재수집은 필요 없습니다. 같은 파일의 실패한 seed-1 처리 결과를 재사용하지 않고 새 파서가 재검사합니다. 구버전은 원본 업로드 파일을 보관하지 않았으므로 프로그램 업데이트만으로 거부됐던 행을 복구할 수는 없습니다.

## 원인
원본 형태는 date=날짜, timestamp/transacttime=57:26.3 같은 불완전한 시간 문자열입니다. v0.4.0은 timestamp를 우선 파싱하다 실패하여 날짜와 walletbalance까지 버렸습니다. 새 파서는 다른 완전한 시각 필드를 먼저 확인하고, 시각이 전부 불완전하면 date를 날짜 단위로만 처리합니다. 잘린 시(hour)를 임의로 붙이지 않습니다.

## 무엇이 표시되는가
- 완전한 날짜·시각이 있는 잔고: 기존처럼 주문 이전 관측 참고값.
- 날짜만 남은 wallet 원장: `이전 기록일 마감 잔고 · 참고`와 기준 날짜를 표시합니다. 그 날짜의 amount·walletbalance 연결을 검산한 후 다음 날짜부터만 사용합니다. 같은 날의 미래 손익은 분모에 쓰지 않습니다.
- 원장의 정방향·역방향 순서가 모두 가능하고 결과가 다르거나 금액 연결이 불일치하면 계산을 보류합니다. 서로 다른 출처의 일별 잔고도 대조합니다.
- 시각 불명 입출금 당일, 36시간 이상 오래된 기준, 계좌 혼합, 0 이하 잔고, 자료 충돌은 보류하며 구체적인 이유를 표시합니다.
- `시드 미연결`과 `잔고 연결됨 / 시드 계산 보류`, `손익자료 미연결`을 구분합니다. 상단에는 시각 잔고 건수 또는 일별 참고 일수를 표시합니다.

**BTC 순손익은 기존 성과 자료 값 그대로입니다. 일별 잔고로 나눈 %는 전일/이전 기록일 잔고 대비 참고 성과이며, 정확한 주문 직전 순자산 수익률·계좌 전체 수익률·실제 투입 증거금 비중이 아닙니다.** 당일 실현손익 및 모든 계약의 미실현손익까지 복원한 버전이 아닙니다. 최종 손익과 주문 전체 수량은 복기에서 해당 체결이 끝난 뒤에만 표시합니다.

## 검사 범위
실제 파일에서 확인된 열과 잘린 시간 형식을 재현한 합성 잔고로 가져오기·같은 파일 재처리·메모 보존·일별 연결 검산·UTC 날짜 경계·미래 잔고 차단·입출금 보류·% 표시·브라우저 새로고침을 검사합니다. 개인 원본을 GitHub나 CI에 게시하지 않습니다. 이 기록은 사용자의 원본 전체에 대한 전수 검산이 아닙니다. 가져오기 후 실제 로컬 자료의 전체 행 수·거부 건수·일별 검산 일수는 앱의 검증 기록에서 확인할 수 있습니다.
