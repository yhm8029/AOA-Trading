# v0.4.0 — 시드 대비 주문 규모와 최종 성과

새 ZIP을 **새 빈 폴더**에 풀고 start_windows.bat 실행. 기존 앱 또는 local-data를 선택하여 DB와 메모 사본을 보존합니다. 자동으로 열린 탭의 v0.4.0을 사용하세요. Python 3.10+ 필요, 추가 pip/API 키는 필요하지 않습니다.

## 사용 순서
1. 이전에 연결한 주문·캔들·성과표는 그대로 유지합니다.
2. 데이터 가져오기에서 **aoa_public_2021-12-31_with_letter.zip** 또는 그 안의 **aoa-wallet-2018-03-01-2021-12-31.csv**를 선택하세요. wallet CSV만 읽으며 원본 실행기록을 공개 서버에 올리지 않습니다. 파일이 PC에서 localhost로만 전달됩니다.
3. 포지션 선택 후 오른쪽 최종 결과에서 BTC 순손익과 **초기 시드 대비 손익 기여도 %**를 봅니다. 최초 진입·각 추가·감량을 누르면 시드 대비 계약규모와 전후 보유비중을 표시합니다.
4. 차트 아래 기준 선택으로 초기 시드 고정/각 주문 직전 시드를 전환합니다. 긴 % 문구는 선택한 마커에만 표시하고 개별 주문 목록에도 비중을 남깁니다.

## 시드의 정확한 뜻
**순자산 equity_btc 자료가 있으면 그것을 사용**합니다. 없다면 **walletBalance(지갑잔고)**를 사용하고 화면에 `지갑잔고 시드 · 미실현손익 제외`를 표시합니다. Wallet-only 값을 순자산이나 실투입 증거금이라고 부르지 않습니다. 현재 파일로 모든 계약의 미실현손익을 다시 복원하는 기능은 이번 범위에 없습니다.

`최종 손익 기여도 = 해당 포지션 순손익 BTC / 최초 진입 직전 시드 참고값 × 100`.
`주문 규모 비중 = 해당 주문의 계약가치 BTC / 선택한 시드 참고값 × 100`.
XBTUSD의 계약가치는 수량/가격, 역수가중 주문가격 우선. 산술평균 또는 첫 체결가격만 있으면 명시적 근사값입니다. 다른 계약에는 XBTUSD 공식을 적용하지 않습니다. 재진입은 주문 규모이며, 보유비중을 주문금액 단순 합계로 구하지 않습니다.

최초 진입 시드는 포지션 최초 관측 진입을 기준으로 합니다. 첫 기록에 이미 수량이 있으면 초기시드 계산을 보류합니다. 형식상 소량 전환 잔량이 최초 진입일 수 있으므로 이를 강한 확신으로 해석하지 않습니다. 보유비중의 관측 최대는 정확한 장중 최대 레버리지가 아닙니다.

## 정확도와 데이터 경계
- 시드 조회는 주문 시각보다 **엄격히 이전** 관측만 사용합니다. 현재 잔고·기말 잔고·미래 자료를 과거 주문에 대입하지 않습니다.
- 동일 시각 잔고 충돌, 다중 계좌 혼합, 0/음수 시드, 36시간 이상 오래된 관측은 계산 보류합니다.
- 날짜만 기록된 입출금/잔고는 해당 날 장중 순서를 임의로 정하지 않습니다. 이후 시각이 명시된 잔고가 확보될 때까지 비중을 보류합니다.
- 비중은 모두 `≈` 과거 잔고 참고로 표시합니다. 원장 한 행이 정확하다는 것과 주문 직전 평가 순자산이 정확하다는 것은 다릅니다.
- 지갑 원문 단위는 currency=XBt이면 satoshi(1e8), BTC/XBT이면 BTC. 단위가 없거나 모호하면 거부 로그에 표시합니다. 값 크기로 추정하지 않습니다.
- 취소·미완료 출금은 제외합니다. 잔고 원장과 실행원장의 알려진 차이를 임의로 보정하지 않습니다.
- 복기 중 최종 손익은 마지막 청산 이후, 주문 전체 수량/가치는 그 주문의 마지막 체결 이후에만 공개합니다.

정규화 CSV는 `timestamp,wallet_balance_btc,equity_btc,account_key` 헤더를 사용할 수 있습니다. 둘 중 확보한 잔고 열만 채워도 됩니다. 공식 추정 순자산 자료는 `equity_estimate_btc`로 구분할 수 있습니다. 템플릿에는 가짜 잔고를 채우지 않았습니다.

## 검증
추가 회귀검사는 과거시점 조인, XBt/BTC 환산, 현금흐름 날짜 불확실성, 다중 계좌·동시 잔고 충돌, 기준 고정/당시 기준, 중복 가져오기, 롱/숏·추가·감량, 복기 중 미래 수량/성과 숨김, 원본 ZIP 형태의 잔고 가져오기, 기존 메모 보존입니다. 합성 자료 CI 검사와 사용자의 실제 원본 전수 검산은 별개입니다. 후자는 완료했다고 주장하지 않습니다.

공식 개념 참고: https://www.bitmex.com/app/pnlGuide 및 https://docs.bitmex.com/api-explorer/get-wallet-history . 계산 입력은 사용자가 직접 연결한 로컬 자료뿐입니다.
