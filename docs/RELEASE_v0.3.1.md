# v0.3.1 — 실제로 새 앱이 열리는지 검증하는 수정판

## 이번에 바꾼 것

스크린샷의 구버전 화면과 포트 충돌 경로를 바탕으로 실행/업데이트 문제를 수정했습니다. 사용자 PC의 실제 원인을 원격으로 확정했다는 뜻은 아닙니다.

- 기존 8765 포트를 다른 프로그램이 사용해도 새 앱이 종료되지 않습니다. OS가 배정한 다른 로컬 포트에 새 서버를 열며 기존 프로세스는 강제 종료하지 않습니다.
- 새 서버의 앱 ID·버전·실행 ID·폴더·프로세스를 확인한 뒤 그 주소로만 브라우저를 엽니다. 옛 탭/즐겨찾기 주소를 재사용하지 마세요.
- 화면이 뜨기 전에 UI와 서버 버전을 대조합니다. 다른 실행 세션의 주소/오래된 파일이 감지되면 기능을 차단하고 원인을 표시합니다.
- ZIP의 파일별 SHA-256을 실제 실행 전에 검사합니다. 덮어쓰기 중 구/신 파일이 섞이면 데이터 열기 전에 중단합니다.
- 화면 오른쪽 위 `실행 확인 v0.3.1`을 펼치면 앱 폴더, 데이터 폴더와 현재 포트를 볼 수 있습니다.
- Windows의 새 폴더 첫 실행에서 기존 데이터 폴더 선택 창을 엽니다. 기존 앱 폴더 또는 local-data를 선택하면 SQLite backup API로 주문·캔들·메모 사본을 새 폴더에 만듭니다. 원본은 삭제하지 않으며 새 폴더의 기존 DB도 덮어쓰지 않습니다. 진행 중 WAL에 커밋된 자료까지 복사합니다.

## 실행 — 기존 사용자는 이것만

1. 새 ZIP을 **새 빈 폴더**에 압축 해제합니다. 옛 프로그램 파일 위에 덮어쓰지 마세요.
2. 새 폴더 안 `start_windows.bat`를 실행합니다. Python 3.10 이상이 필요합니다.
3. 폴더 선택 창이 나오면 기존 AOA 앱 폴더 또는 `local-data`를 선택합니다. 데이터 전부를 다시 가져올 필요는 없습니다. 취소하면 새로운 빈 데이터로 시작합니다.
4. 자동으로 열리는 **새 브라우저 탭**에서 `v0.3.1`과 `실행 확인 v0.3.1`을 확인합니다. 이전 탭의 127.0.0.1:8765 주소는 계속 옛 앱일 수 있습니다.

사본이므로 복사 완료 후 옛 앱에서 새로 작성한 메모는 새 앱에 자동 동기화되지 않습니다. 복사 중에는 옛 앱에서 가져오기/메모 작업을 마치는 것이 좋습니다. `local-data/last-launch.json`에 현재 검증 URL이 저장됩니다. 프로그램은 기존 Python 프로세스를 강제 종료하지 않습니다.

기존 DB를 이미 새 앱의 local-data에 복사했다면 바로 시작합니다. 수동 폴더 선택: `start_with_existing_data.bat`. 새 폴더에 이미 DB가 있을 때는 재복사하지 말고 유지하세요.

CLI:
```
python run.py --copy-data-from "D:\old AOA app" --no-browser
python run.py --data-dir "D:\AOA-data"
python run.py --self-check
```
`--data-dir`은 지정 폴더를 직접 사용합니다. `--copy-data-from`만 안전한 사본을 생성합니다. 소스 체크아웃에는 배포 manifest가 없을 수 있으며 이 경우 source-checkout으로 표시됩니다.

## 차트/매매 복기

v0.3 기능을 포함합니다: 첫 진입으로 이동, 소액 진입/마지막 감량 필터 보호, 전체 타임라인, 실제 캔들 마커, 주문별 사전 캔들·거래량 근거 해설, 주문에서 멈추기, 여러 시간대, 누락 시세 보완, 호버 등락률, 성과 참고값, 메모와 내보내기.

15분봉도 누락된 1분봉을 실제로 확보한 뒤 재집계합니다. 상장 전/거래소 공백/접근 제한/격리된 충돌은 임의 가격으로 메우지 않습니다. `누락 시세 자동 보완`과 진행/누락 수를 확인하세요. 복기에서 주문을 포함한 봉이 아직 완성되지 않았으면 마커도 아직 나오지 않습니다. `주문이 나오면 멈추고 해설` 체크는 의도된 자동 일시정지이며 끄면 계속 재생됩니다.

## 한계와 검사

해설은 로컬 규칙 기반 연구 가설입니다. 고래의 실제 의도를 확정하거나 모든 매매법을 학습한 AI 예측기가 아닙니다. 체결 전 정보만 쓰며 이익/손실/레버리지 수익률을 임의로 생성하지 않습니다.

Windows/Linux Python 3.10/3.13 단위 검사와 Chromium 4종 검사를 수행하고, 압축을 푼 **실행 ZIP 자체**를 한글·공백 경로에서 다시 띄워 포트 충돌·기존 데이터 복사·마커·해설·재생을 검사합니다. 거래 테스트는 명시적 합성 자료입니다. 실제 공개 Binance 시세 검사는 별도이며 사용자의 전체 ZIP 전수 검산은 아닙니다.

개인 거래자료·DB·메모·키·폰트 파일은 배포하거나 GitHub에 업로드하지 않습니다.
